# 协作分工说明

> 仓库：https://github.com/jsadin/Robot_Controller_GUI  
> 主分支：`main`（受保护，只接受 PR 合并）  
> 更新：2026-08-01

本文约定：**谁改哪一块、如何用 Git 防冲突、当前待办如何分工验收**。

---

## 1. 协作原则（先读）

1. **设备层与 UI 分层**：`devices/` / `core/` 不依赖 PyQt；UI 只发信号、调门面。跨层改动必须同 PR 说明。
2. **一人一块主责模块**，他人改该目录需先沟通或发小 PR。
3. **禁止直推 `main`**：一律 `feature/*` → Pull Request → Review → Merge。
4. **密钥不进库**：`config/devices.local.yaml`、相机密码、个人 IP 只留本地；公共默认写 `config/devices.yaml`（无密码）。
5. **真机联调前先跑冒烟**：`python scripts/live_device_test.py`（用带 `elite_cs_sdk` 的 ES66 venv）。

## 2. Git 协同与防冲突

### 2.1 推荐分支模型

| 分支 | 用途 |
|------|------|
| `main` | 可演示/可联调基线，始终可启动 |
| `feature/<谁>-<简述>` | 功能开发，例：`feature/alice-arm-seq-loop` |
| `fix/<谁>-<简述>` | 缺陷修复，例：`fix/bob-estop` |
| `test/<日期>-checklist` | 可选：集中补测试脚本，不掺业务大改 |

### 2.2 日常流程（每人）

```text
git fetch origin
git checkout main
git pull origin main
git checkout -b feature/你的名字-功能名
# ... 开发、自测 ...
git add <相关文件>
git commit -m "类型: 简述（为何）"
git push -u origin HEAD
# 在 GitHub 开 PR → 指定 Reviewer → 合并后删分支
```

提交信息建议：`fix:` / `feat:` / `docs:` / `test:` / `refactor:`，一句说清**为什么**。

### 2.3 目录锁（减少冲突）

| 目录 / 文件 | 主责（角色） | 他人改动规则 |
|-------------|--------------|--------------|
| `devices/chassis/`、`ui/control_panel.py`、`ui/map_canvas.py`、`tasks/` | **底盘** | 改接口先改 `docs/INTERFACE_SPEC.md` |
| `devices/arm/`、`ui/arm_*.py`、`ui/action_sequences_dialog.py`、`config/rtsi/` | **机械臂** | 对照 `ES66/` 只读源，勿改旧仓 |
| `devices/camera/`、`ui/vision_panel.py` | **视觉** | 抓拍路径统一 `~/.robot_controller/snapshots` |
| `core/mission.py`、`ui/mission_panel.py` | **任务组** | 步骤模型变更需通知底盘+臂 |
| `devices/common/estop_bus.py`、急停相关 | **安全**（可与底盘兼任） | 任何急停改动必须双人 Review |
| `ui/workspace.py`、`ui/panel_host.py`、`ui/float_panel.py`、`ui/theme.py` | **壳层 UI** | 分屏/主题大改单独 PR |
| `ui/main_window.py` | **壳层 UI（协调）** | **热点文件**：每次 PR 尽量小；合并前必 `git pull --rebase` |
| `config/devices.yaml`、`docs/*` | 轮值 / 文档 | `devices.local.yaml` 永不提交 |
| `scripts/`、`tests/` | 测试轮值 | 冒烟脚本破坏兼容需全员知会 |

### 2.4 防冲突实操

1. **缩小 PR**：一个 PR 只做一类事（例：只修急停，不顺手改分屏）。
2. **`main_window.py` 冲突高发**：改接线时只动自己相关的 `connect` / 回调段；大改前先开 Issue 占坑。
3. **合并前**：
   ```bash
   git fetch origin
   git rebase origin/main   # 或 merge，团队统一一种
   ```
4. **同一文件并行**：用 GitHub 的 Draft PR 提前暴露 diff；或约定「谁先占 Issue 谁先改」。
5. **禁止**：`git push --force` 到 `main`；共用一个长期 `dev` 无 Review 堆代码。
6. **真机资源**：底盘 / 臂 / 相机同时只能一人独占联调；日历上预约「联调时段」。

### 2.5 建议的 CODEOWNERS（可选，GitHub）

在仓库根增加 `.github/CODEOWNERS`（按实际 GitHub 用户名改）：

```text
/devices/chassis/          @底盘负责人
/devices/arm/              @机械臂负责人
/devices/camera/           @视觉负责人
/core/mission.py           @任务组负责人
/devices/common/estop_bus.py @安全负责人
/ui/main_window.py         @壳层负责人 @底盘负责人
```

## 3. 当前问题清单与分工

状态：`P0` 阻塞联调/安全 · `P1` 功能完整性 · `P2` 体验增强

| ID | 问题 | 优先级 | 主责 | 涉及路径 | 验收标准 |
|----|------|--------|------|----------|----------|
| A1 | 底盘速度调节「感觉无效」 | P0 | 底盘 | `ui/control_panel.py`、`ui/main_window.py` `on_move_tick`/`on_max_*`、`devices/chassis/client.py` | 滑块松开后状态栏显示读回值；遥控前后/转向速度随滑块明显变化；角速度≤0.8 |
| A2 | 急停未生效 / 不可靠 | P0 | 安全+底盘+臂 | `devices/common/estop_bus.py`、`MainWindow.on_estop`、臂 `emergency_stop` | 一点急停：底盘停且拒动、臂停发 servoj、Mission/ChassisTask 中断；解除后行为符合文档 |
| A3 | 机械臂动作组无循环、无步间延时 UI | P0 | 机械臂 | `ui/action_sequences_dialog.py`（对照 `ES66/.../action_sequences_dialog.py`）、`devices/arm/sequences.py` | 可勾选循环；每步可设延时（≥5s 与原版一致）；运行时按延时等待 |
| A4 | 跨设备任务组（Mission）功能不全 | P1 | 任务组 | `core/mission.py`、`ui/mission_panel.py`、与 POI/动作组选择器 | 可编辑步骤：导航 POI / 等 / 跑动作组 / 抓拍；执行有进度；急停可打断 |
| A5 | 巡检日历是否可用 | P1 | 底盘 | `ui/task_dialog.py`、`tasks/scheduler.py`、`MainWindow._check_schedule` | 单次（日历日期+时间）与每日触发；到点自动启动 ChassisTask；防同日重复 |
| A6 | 抓拍如何生效 / 路径不清晰 | P1 | 视觉 | `ui/vision_panel.py`、`on_camera_snapshot`、`devices/camera` | 先开摄像头再抓拍；文件落到 `~/.robot_controller/snapshots/`；状态栏显示路径；Mission 步骤 snapshot 同样落盘 |
| A7 | 全功能回归未做 | P0 | 测试轮值 | `docs/协作分工说明.md` 第 5 节清单 | 清单全部勾选或注明「阻塞原因+Issue」 |

### 3.1 问题说明（给主责的技术要点）

**A1 底盘速度**  
远端已合入 `speed_ratio` 遥控与参数读回。若仍「无效」：确认松开滑块后状态栏是否有「读回确认」；转向速度受实机约 **0.8 rad/s** 封顶。继续问题时抓：策略名、读回值、是否在遥控中测试。

**A2 急停**  
检查：连接底盘后 `estop_bus.bind(chassis=...)` 是否执行；臂已连接时 `arm.emergency_stop`；物理急停与 UI 急停状态同步（`poll` 里 `set_estop_state`）。建议加「急停联调」专项，勿与大 UI PR 混提。

**A3 动作组**  
整合版 `action_sequences_dialog.py` 目前只能新建组、加步、运行，**缺少**原版的循环开关与每步延时编辑。存储层 `devices/arm/sequences.py` 已支持 `loop` / `delay_after_s`，优先补 UI + 运行逻辑，对齐 ES66 独立版。

**A4 任务组**  
`Mission` 模型已有，面板偏「示例创建」。需补：步骤编辑器、选星标/选动作组、执行进度展示、与急停联动回归。

**A5 日历**  
`TaskDialog` 已有日期控件 + `check_due` 轮询。需真机验证：到点是否触发、时区/本机时间、任务面板状态刷新。

**A6 抓拍**  
逻辑已接：需摄像头已 `open` 且有帧。建议 UI 增加「上次保存路径」展示；未开相机时按钮提示。

## 4. 角色分工（建议 3～4 人）

| 角色 | 职责 | 本迭代交付 |
|------|------|------------|
| **壳层 / 集成** | 分屏壳、`main_window` 接线、发版、冲突协调 | 协调 A7；Review 所有碰 `main_window` 的 PR |
| **底盘** | 地图/遥控/星标/ChassisTask/日历/速度 | A1、A5；参与 A2 |
| **机械臂** | 连接/RTSI/动作组/调速 | A3；参与 A2、A4（动作组步骤） |
| **视觉 + 任务组**（可一人兼） | 预览/抓拍；Mission 编排 | A6、A4 |
| **测试轮值**（每周轮换） | 清单执行、写 Issue、挡住不合格合并 | A7 |

人数更少时合并：**壳层+测试**、**底盘+急停**、**臂+视觉+Mission**。

## 5. 全功能测试清单（合并 `main` 前）

环境：ES66 venv + `PYTHONPATH=仓库根`；`devices.local.yaml` 已配 IP/密码。

### 5.1 启动与连接

- [ ] 启动无闪退（SDK 先于 Qt）
- [ ] 连接底盘成功，地图可拉
- [ ] 连接机械臂，滑块显示非全 0 的真实关节角
- [ ] 打开摄像头有画面

### 5.2 底盘

- [ ] 遥控四向 + 停止
- [ ] 线速度/角速度滑块：读回正确，遥控体感变化
- [ ] 星标添加/前往/删除
- [ ] 回桩、重定位、虚拟墙（抽样）
- [ ] ChassisTask 新建/执行/暂停/中断
- [ ] 日历：单次、每日各测一次触发

### 5.3 机械臂

- [ ] 关节拖动（流控开）可动且无持续超速报警
- [ ] 动作组：记录位姿、设延时、循环开/关、运行完整
- [ ] 断连/重连后滑块重新同步

### 5.4 视觉

- [ ] 抓拍成功，磁盘可见 jpg，状态栏有路径
- [ ] 关闭相机后再抓拍有明确失败提示

### 5.5 任务组 / 安全 / 壳

- [ ] Mission：至少「导航或等待 + 动作组或抓拍」串行跑通
- [ ] 急停：底盘+臂+任务均停；解除后可恢复操作
- [ ] 分屏：总览 / 放大 / 弹出停靠 / 移到

### 5.6 回归记录

每人测完在 Issue 或 PR 描述贴：

```text
日期 / 测试人 / 固件或备注
通过: ...
失败: ...（附日志或截图）
```
